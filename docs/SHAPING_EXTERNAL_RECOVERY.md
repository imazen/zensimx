# Recovery after external interruption

The owner permits recovery after an external termination or disk/memory resource
fault, after its cause is fixed. This does not approve dropping whole interrupted
settings, changing the selector, or calling a weight-only warm start an exact
continuation. Preserve the original registration and every interrupted attempt.

Four pretrained worker attempts ended when the user service manager shut down
after SSH logout with lingering disabled. None completed an epoch or wrote an
epoch checkpoint. Once lingering is enabled and verified, their last recoverable
boundary is the original seeded initialization. `shaping_external_recovery.py`
admits only these four fixed cells, as attempt 002, under a separately pinned
owner-direction record. It retains the frozen binary, original command and
scientific arguments, shape bank and features; only output locations change.
No completed training epoch or pretraining prefix is replayed. Independent jobs
use the existing shared CPU/RAM admission and SSD reservation. Launch them through
persistent worker services and retain both the interrupted and recovered records.
The known pretrained-threshold initialization limitation remains part of these
original frozen conditions; this recovery does not silently substitute its fix.

Collection of a later attempt requires that explicit authorization, the original
external/zero-epoch failure evidence, unchanged build identity and matching
recovery pins in RUN and RESULT. Unrelated later attempts still fail admission.
The normal complete-checkpoint and native scientific evaluation gates remain.

Two older interrupted joint-shaping fits retain 19 and 219 of 240 epoch
checkpoints. Their saved bakes contain model parameters/scalers, not optimizer
and sampler state; the existing warm-start path starts fresh Adam and shared
depth refuses it. They cannot be described as exact continuations from those
bakes. Their causes remain unconfirmed. Resource evidence and any proposed
recovery need separate resolution; this zero-epoch helper cannot admit them.
