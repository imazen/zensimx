# Corrected-condition execution

The immutable approved registration remains separate from activation and from
the original PLAN/MATRIX. `shaping_corrected_view.py` validates its evidence and
constructs a comparison view by replacing only the 288 pretrained-head IDs.
All other cells and all original files remain unchanged. There are 816 effective
primary conditions: 288 corrected heads and 528 retained controls, alongside
the existing 72 fresh inner controls. Historical pretrained-head reports fail
the corrected selector's exact paired-report coverage check.

The compatibility certifier requires all six prespecified neural control
classes, their exact original final models, all 240 epochs, the corrected
binary identity and the permitted metadata-removal scope. It refuses missing
epochs, intermediate mismatches, changed originals and nonterminal fits.
Certifying writes no activation and launches no training. Explicit activation
requires that certificate before any outer admission. The loader then supplies
the corrected comparison view while retaining an explicit original-only view
for provenance. Parent-bank reuse admits only the registered matching parent
and the original build of its qualified control class. New corrected fits
require the corrected binary, 120 epochs, and bounded full-state snapshots.
Registration alone does not enable them.

The base selector, rescue resolver/dispatcher, selection watcher and outer
admission all use the same corrected base-selection path. Unchanged ReLU
rescues retain their IDs and decisions. Existing rescue trigger coverage and
the original whole-setting undefined policy remain in force.

`shaping_corrected_worker.py` captures the effective condition, activation,
TRAIN tables, matching completed parent's epoch-119 bank, source modules and
native binaries in the existing bounded worker capsule. The worker reproduces
that gate before shared CPU admission and runs the existing 120-epoch command
owner with a 2-GiB cap. Collection revalidates the corrected condition in both
RUN and RESULT before publication. The owning wait records the live snapshot
lock beside the run; binding failures are explicit artifacts and never signal
or restart the trainer.

The real frozen-study readiness check refused an unactivated corrected ID
before an attempt existed. Worker capsule/controller fixtures passed; native
corrected scientific fitting and its transport qualification remain unexecuted.

Human-only analytic neutral qualification has its own worker CPU/SSD admission
key, distinct from the simultaneously running full control. Its two one-epoch
arms still use the same four admitted human populations, zero teacher rows and
50,000 pairs per epoch. The existing portable command owner resolves collected
declaration paths. This capability does not reuse qualification from another
binary or expose outer responses.

Completed compatibility controls use `shaping_control_evidence.py` to inventory
all 240 finalized native bakes, terminal receipts and resource logs against the
exact comparison ledger. Collection excludes canonical intermediate copies and
retains their hashes in the terminal ledger. It references the original control
and shared TRAIN inputs by their existing identities rather than copying them
again. Snapshot archival has its separate binding/readback owner. Missing or
changed native bakes refuse collection.

Transport capsules may use `just shaping-lossless-capsule SOURCE OUTPUT` for
standard single-thread zstd compression, with the original raw SHA-256,
compressed SHA-256 and complete decompressed-byte comparison in a sidecar.
The owner creates the destination parent, preserves existing output, keeps the
raw source and maintains the SSD reserve. A real 29,736,960-byte input capsule
produced the same 15,852,985-byte compressed object and exact raw hash through
this reusable owner. This changes storage representation, not training data.

The frozen four-setting matrix and the archived monotone-SiLU trajectory were
accepted by these checks on November 8, 2026. Five other native control
qualifications were still running; no activation was written. Fixture checks establish orchestration
behavior; they do not complete those native qualifications or corrected fits.

Once explicitly activated, affected base-selection paths use the
`-corrected-threshold-base.json` suffix. Existing selections remain historical
evidence. Unchanged families retain their established selection paths.
