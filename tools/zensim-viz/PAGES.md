# A explorer preparation

The Pages page computes detector maps and PDP/ICE in a single-thread SIMD Wasm
worker. It embeds only shipped A, SHA-256
`d5e2a56db35c32620d9f9d9c19ba3bc78bd8fea2b8cd933cde8447428d85e62a`.
The native exporter, observer and all frozen audit/curve gates remain available.
The Pages Wasm build exports the atlas/lens API only; normal workbench builds
retain their attribution and loop APIs. This prevents an unused built-in B
profile, including its historical provenance, from entering the public module.

A browser-local image pair is decoded by the browser as opaque sRGB8, not by
zenjpeg. Pair dimensions must match. HDR means a reference TRAIN feature bank;
the image atlas does not claim native HDR decoding. The synthetic default pair
is generated by code. There are no packaged sample image assets.

The tree identifies every declared model input, including raw damage × fragility.
Links from coefficients and concerns open the corresponding explained feature.
Output-layer indexes identify hidden units; their links open those units.
The function shows certified max pairs, the complete always-active affine
background, stored input coefficients and native output calibration. Bounds
apply on the stated domain before calibration. No memorization experiment is
performed, and the page does not claim absence of memorization.

Each bank contains 200 deterministic observed rows of consumed raw slots in
f32 little-endian order, plus full-population raw and declared-input quantile
grids. Wasm uses BakeScorer for all served scores, fragility products, individual
and joint family interventions, centered bands, ablations and separation.
Human ratings are not inferred from teacher targets. Audit observations are
labelled SDR TRAIN even while viewing HDR curves.

## One range-readable object

`pack/` reuses the native IMIJ-set Writer and Reader. It checks every entry's
native checksum and exact decoded bytes. `pages_build.py assemble` places a
64 KiB application catalog first, then binary/JSON payloads and the native
index/footer. The browser supports this immutable single-generation profile,
checks footer identity and bounds, requests each payload with HTTP Range, and
verifies its SHA-256 in Wasm. It does not implement the general IMIJ image codec.
The footer's native checksum/index are checked by the preparation reader; the
browser checks each catalog-addressed payload independently.

Only `bundle.imijset` is eligible for R2 upload, under the pinned public source
commit. The catalog and compressed payloads are internal entries, not separate
objects. `r2_pages.py` disables write retries and multipart upload, refuses an
existing immutable object, enforces the 10 MB data and 100 GB bucket limits,
requires passing browser/parity/budget evidence, and records its one PUT before
performing HEAD and full readback verification. Resolve any failed PUT before
retrying; never assume a network failure means no object was written.

## Qualification and publication boundary

Set disk-backed `TMPDIR` and `JUST_TEMPDIR` before invoking Just. The
`viz-pages-qualify` recipe serializes native extraction, both bank exports,
function/audit exports, frozen F0 tests, clippy and Wasm compilation under the
shared heavy lock and resource wrapper. Put the frozen F0 census bake at the
SHA-named path in that output root, or set `VIZ_F_BAKE` explicitly.
`viz-pages-parity` checks scores at
1e-6 and every detector cell/map sum at 1e-4, relative to max(1, native magnitude).
Native control/instrumented pooled f64 comparisons tolerate no changed bit.
`viz-pages-lens-check` compares both banks' curves, centered statistics, every
rise witness, family interventions and diagnostics with native execution.
`viz-pages-smoke` checks range transport, feature joins and both viewport sizes
and themes. Its screenshots and receipts stay outside git.

`pages_census.py` counts all tracked code/config/templates in this tool and the
workbench, both metric observer modules and the shared integration
additions. It includes native preparation and historical tests. It excludes prose,
lockfiles and generated artifacts. `--enforce` requires fewer than 500,000 bytes.
The separate pre-existing JPEG XL loop-convergence CLI is outside this census;
it is not a dependency of the Wasm build. The complete IMIJ-set must be no
larger than 10,000,000 bytes.

`pages/pages.yml.in` is a dispatch-only workflow template for imazen/zensim.
`pages_build.py workflow` writes the exact new-file diff using a pinned public
zensimx source commit. It does not enable Pages or write to that repository.
The coordinator installs and dispatches the workflow only after owner review.
See REPORT.md for actual qualification results and any outstanding gates.
